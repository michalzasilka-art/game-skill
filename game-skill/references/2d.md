# 2D reference

Skills to load when installed: `phaser-core`, `phaser-arcade-physics`, `pixijs-rendering`, `create-game-assets`, `sprite-gen`, `game-ui-ux`, `game-feel`, plus the genre skill (`platformer`, `puzzle`, `card-game`, `visual-novel`, `tower-defense`, `roguelike`…). Full list: `skill-index.md`.

## 1. Engine choice

| Need | Use | Why |
|---|---|---|
| A link that works on any phone, quiz / board / puzzle / arcade | **Plain Canvas 2D or DOM + CSS** | zero build step, smallest download, easiest text layout |
| Physics, tilemaps, many scenes, arcade action | **Phaser 4** | scenes, loader, arcade physics, tweens built in |
| Thousands of sprites, filters, particles | **PixiJS v8** | fast WebGL batching |
| App stores / desktop, big content | **Godot 4** (or Unity 2D) | editor, export templates, tilemaps |
| Typed web project that will grow | **Vite + TypeScript** + any of the above | modules, hot reload, a real build |

Stay with what the project already uses. Don't switch engines mid-project.

## 2. Screen and layout

- Design at **1080×1920 portrait** (or 1920×1080 landscape) and scale to fit with letterboxing; keep a safe area (~6 % each side) for notches and rounded corners.
- The game must also work at the other orientation / 16:9 — at least as a centred column with a decorative background.
- Text: min ~28 px at 1080 width for body text, 40+ for buttons. Every label must survive the longest real string (test it).
- Touch targets ≥ 48 px (CSS) and never closer than 8 px to each other.
- Test at 390×844 (phone), 360×640 (small phone) and 1280×720.

## 3. Art pipeline

1. **Style guide** (`create-game-assets`): palette of 12–20 hex colours, line weight, shading style (flat / 2-tone / painted), what is NOT allowed (pure black outlines? gradients? text in art?).
2. **One style frame** — a mock screenshot of the game — approved by the user. It is the reference for everything after.
3. **Character sheet** — the hero front / side / back / 3–4 expressions, on a flat background.
4. **Assets from the references**: always attach the style frame / character sheet when generating more pictures so they match.
5. **Clean-up:**
   - Real transparency: open the PNG and check the alpha channel. AI tools sometimes paint a checkerboard or a white box instead. Fix with a chroma-key (generate on flat magenta or green), or a background-removal step.
   - Trim empty borders, set the pivot (feet for characters).
   - Make sprites at 2× on-screen size; export WebP (quality 80–90); keep the PNG originals in an `art/` folder outside the build.
6. **Atlases:** pack sprites into sheets ≤ 2048×2048 for phones (4096 max on desktop). One atlas per scene keeps draw calls low.
7. **Record** each asset's source, prompt and licence in a manifest (`create-game-assets`). Some stores (e.g. Steam) ask about AI-generated content.

## 4. Animation

- Characters: 6–12 fps frame animation (idle 4–6 frames, walk/run 6–8, jump 3–5, react 4–6). Generate a pose sheet from the character sheet, slice it, check the frames line up (same feet height, same scale).
- Everything else: tweens — squash and stretch on landing, overshoot on pop-in, ease-out on movement, a small rotation wobble on idle UI.
- Living backgrounds and cutscenes: short video loops (MP4 H.264 + WebM fallback, `muted autoplay loop playsinline`), 2–6 s, ≤ 2–4 MB each; a poster frame shows while it loads. Image-to-video tools (Higgsfield / Seedance / Grok video) make them from your approved pictures.
- Parallax: 3–4 layers, far layers move 0.1–0.3× the camera.

## 5. Budgets

| What | Phone target |
|---|---|
| First load (before the menu is interactive) | ≤ ~5–10 MB |
| One scene's art | ≤ ~10–15 MB, loaded behind a progress bar |
| Frame rate | 60 fps on a mid-range phone, no drops on input |
| Draw calls (WebGL) | < 100 — use atlases |
| Video loops | ≤ 4 MB each, ≤ 2 playing at once |
| Audio | music OGG/MP3 ~96–128 kbps; SFX short, preloaded |

## 6. Prototype vs in between vs final

- **Quick prototype:** shapes in code (rectangles, circles, emoji are fine), real rules and scoring, one level/mode, placeholder sounds, published as a preview link. No AI art spent yet.
- **In between:** the approved style frame and the hero art in the game, a menu, one polish pass (juice, sounds), phone test.
- **Final version:** full art set from the style guide, a menu scene with the hero, all animations, sounds and music, cutscenes if the story needs them, all screens tested on phone + 16:9, published with a cover image.

## 7. 2D game-feel checklist

- Coyote time + jump buffer for platformers (`platformer`), exact undo for puzzles (`puzzle`).
- Hit-stop 40–80 ms, screen shake by "trauma" (decays), particles on success, a sound for every tap.
- Buttons react on press (scale 0.95) and on release; disabled states look disabled.
- Never hide the important text under a popup or a finger.
