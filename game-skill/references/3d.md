## 1. Triangle budgets per answer

Triangles are counted **per frame, in the busiest view, including the shadow pass**. Set the budget once and write it into every brief (Blender, the AI generator, the image prompts).

| Slot | 30–50k (extreme low poly) | 100k (phones, web) | 300–500k (desktop web) | 1M+ (PC / console) |
|---|---|---|---|---|
| Hero character | 1–3k | 5–9k | 15–30k | 30–80k + LODs |
| Rival / 2nd character | 1–2k | 3–9k | 10–25k | 20–60k + LODs |
| Crowd / NPC (each) | 100–300 | 300–1,000 | 1–3k | 3–10k, LOD + impostors |
| Near set + ground | 8–12k | 25–35k | 80–150k | streamed, LODs |
| Far background | 1–3k | 5–10k | 15–30k | impostors / HLOD |
| Props (all) | 5–8k | 15–20k | 50–80k | culled per area |
| Effects | ≤ 1k | 1–3k | 5–10k | GPU particles |
| Shadow pass | 3–6k | 10–20k | 40–80k | cascades |
| Spare | 10 % | 10 % | 10 % | 10 % |
| Draw calls | < 80 | < 150 | < 400 | < 2–5k |
| Texture per character | 256–512 px palette | ≤ 1024 px | 2048 px | 2–4k + LODs |

General platform limits (from the optimisation skills): mobile ≈ 100–300k visible triangles and < 100–200 draw calls; PC ≈ millions of triangles and < 2–5k draw calls. Roblox MeshParts ≤ 20k each.

### How to measure

- **three.js:** `renderer.info.render.triangles` read right after `renderer.render(scene, camera)` (before any post pass; `info.autoReset` is on by default so the number is that frame's scene + shadow map). Log the busiest moment, not the menu.
- **Blender:** Statistics overlay, or the `blender-game-optimization` stats script (`--budget mobile|web|pc`).
- **Unity:** Game view Stats / Frame Debugger. **Godot:** the Monitors tab (Primitives in frame).
- Count visible meshes × instances when you plan, then confirm in the running game.

### Spending rules

- Detail goes where the camera looks: faces, hands, the hero prop. Ground, buildings, far props get the least.
- Cylinders 6–12 sides for props, 16 only for hero items. Spheres as icospheres (subdivision 1–2).
- Never deliver a model "just in case" detailed: the job decides the count. Re-check every model that comes back from a generator — they often return 10–50× the budget.
- Static scenery: merge per material per area (e.g. one mesh per 32 m square) so culling still works. Don't merge across the whole map.
- Repeated things (trees, rocks, fans, coins): `InstancedMesh` / GPU instancing. NPC crowds don't cast shadows.

## 2. Blender MCP workflow

Needs Blender running with the MCP add-on. Load `blender-core` first; it routes to the other blender-* skills.

1. `get_addon_status` (Blender version, what's enabled) and `get_scene_info`.
2. Set up the scene for games: metres, Z-up in Blender, origins at the feet / base centre, names like `SM_Rock_01`, `SK_Hero`.
3. Build with `execute_blender_code` in small steps; after each step call `look` and fix what you see. Silhouette first, then big facets, then bevels.
4. Low-poly look: one palette material (or vertex colours), flat shading on scenery, smooth (by angle) on characters; sink objects slightly into the ground.
5. Existing assets: `search_assets` → `import_asset` (Poly Haven, Sketchfab, Poly Pizza). AI model: `generate_3d` (one object per generation; costs a credit). Imported models come at random scale — size them from the reported bounding box and put them on the ground.
6. **QA gate before export** (`blender-asset-qa`): normals, non-manifold, floating parts, z-fighting, unapplied scale, triangle count vs budget, UVs.
7. Characters: rig on a standard skeleton (Mixamo / Unity Humanoid names), ≤ 20 in-place clips, write `ANIMS.md` with each clip's event frames.
8. Export GLB (web) or FBX (Unity/Unreal) with the `blender-export-pipelines` preset; render a contact sheet (front, side, back, 3/4) to check.
9. Pack for the web: `npx gltfpack -i in.glb -o out.glb -cc -kn -km` (add `-vtf` if the game animates UVs). Load with `MeshoptDecoder`.

Don't run Decimate or `gltfpack -sa` over AI-generated textured models — the textures smear. Retopologise or re-bake instead.

## 3. Code modelling (three.js)

Build the world in code when the shapes are simple and stylised; it is instant, tiny to download and easy to change.

```js
import * as THREE from 'three';
import { mergeGeometries } from 'three/addons/utils/BufferGeometryUtils.js';

// Faceted low-poly rock: an icosphere, jittered, flat-shaded, one colour per face
function rock(radius = 1, color = 0x9a8c7a, seed = 1) {
  let g = new THREE.IcosahedronGeometry(radius, 1);
  const p = g.attributes.position, rnd = mulberry32(seed);
  for (let i = 0; i < p.count; i++) p.setXYZ(i, p.getX(i) * (0.8 + rnd() * 0.4), p.getY(i) * (0.6 + rnd() * 0.3), p.getZ(i) * (0.8 + rnd() * 0.4));
  g = g.toNonIndexed();                    // separate faces -> hard facets
  g.computeVertexNormals();
  shadeFaces(g, new THREE.Color(color), 0.10, rnd);  // ±10 % per face
  return g;                                 // 80 triangles
}

function shadeFaces(g, base, amount, rnd) {
  const n = g.attributes.position.count, col = new Float32Array(n * 3), c = new THREE.Color();
  for (let f = 0; f < n; f += 3) {
    c.copy(base).offsetHSL(0, 0, (rnd() * 2 - 1) * amount * 0.5);
    for (let v = 0; v < 3; v++) c.toArray(col, (f + v) * 3);
  }
  g.setAttribute('color', new THREE.BufferAttribute(col, 3));
}

const paletteMat = new THREE.MeshStandardMaterial({ vertexColors: true, flatShading: true, roughness: 0.9 });

// Many rocks = one draw call
const rocks = new THREE.InstancedMesh(rock(1, 0x9a8c7a, 7), paletteMat, 200);
// ...set each instance matrix, then rocks.instanceMatrix.needsUpdate = true

function mulberry32(a){return()=>{a|=0;a=a+0x6D2B79F5|0;let t=Math.imul(a^a>>>15,1|a);t=t+Math.imul(t^t>>>7,61|t)^t;return((t^t>>>14)>>>0)/4294967296}}
```

Rules:
- One shared palette material for the whole world; colour lives in vertex colours.
- Build composite props (a kart, a house) from a handful of boxes/cylinders/extrusions, `mergeGeometries` them into one geometry per material, and keep the source function so variants are one parameter away.
- Seed every random choice so the world is the same on every load.
- Keep a `models-source.js` (or similar) that can also export GLBs with `GLTFExporter` when another tool needs the model.
- A grey test character (~500 tris, standard skeleton, 20 basic clips) lets you build movement and the camera before the real hero exists.

## 4. AI 3D generator pipeline (Tripo / Higgsfield 3D / Meshy)

1. Reference picture first (`image-tools.md`): front view, A-pose, flat colours, plain white background, the whole body in frame. For a character also a side and back view if the tool accepts several images.
2. **Get the user's approval of the picture** before any 3D.
3. Generate with a polygon target about 20 % under the budget (smart/low-poly mesh mode), then texture.
4. Rig automatically (Mixamo-compatible skeleton) or in Blender (`blender-character-rigging`).
5. Clean: retopo or re-bake if it's too heavy; fix the scale (metres), facing (+Z forward in three.js), origin at the feet.
6. Pack with gltfpack, load, count triangles, look at it in the game's light.

## 5. Lighting presets (three.js r15x+ physical units)

Common setup for all presets:

```js
renderer.outputColorSpace = THREE.SRGBColorSpace;
renderer.toneMapping = THREE.ACESFilmicToneMapping;   // or AgX
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = THREE.PCFSoftShadowMap;
renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
```

### Warm low sun (Recommended)

```js
const sun = new THREE.DirectionalLight(0xffd9a8, 2.4);     // warm, low: 20–35° above the horizon
sun.position.set(-30, 16, 22);
sun.castShadow = true;
sun.shadow.mapSize.set(2048, 2048);                         // 1024 on weak phones
Object.assign(sun.shadow.camera, { left: -25, right: 25, top: 25, bottom: -25, near: 1, far: 120 });
sun.shadow.bias = -0.0004; sun.shadow.normalBias = 0.02;
// Move sun + sun.target with the camera each frame so the shadow box follows the player.

const hemi = new THREE.HemisphereLight(0xfff0d8, 0x7d6a8c, 0.9);  // warm sky, violet-brown ground
const rim  = new THREE.DirectionalLight(0xa9c8ff, 0.5);           // cool rim from behind the player
rim.position.set(20, 10, -30);
scene.fog = new THREE.Fog(horizonColor, 40, 220);                 // fog = the sky's horizon colour
```
Long soft shadows, coloured shade, a painted sky dome (one sphere with an equirectangular picture) or a gradient sky.

### Bright day / cartoon

```js
const sun = new THREE.DirectionalLight(0xffffff, 2.0); sun.position.set(-10, 40, 15); // high sun, short shadows
const hemi = new THREE.HemisphereLight(0xdff1ff, 0xb5d48a, 1.4);                      // strong, sky-blue + grass fill
```
Cheapest look: drop shadows to blob shadows (a dark transparent circle under each character) on weak phones, or use `MeshToonMaterial` with a 3-step gradient map for cel bands.

### Night / neon

```js
const moon = new THREE.DirectionalLight(0x9fb4ff, 0.6); moon.position.set(20, 30, -10);
const hemi = new THREE.HemisphereLight(0x1d2a55, 0x120d1e, 0.6);
// Lamps and signs: MeshStandardMaterial({ emissive, emissiveIntensity: 2–4 }) + a few PointLights (≤ 4 on phones, no shadows)
// Bloom/glow only on things that really emit light.
scene.fog = new THREE.FogExp2(0x141a33, 0.018);
```

### Indoor / studio

Key light 45° to the side and above (shadows on), fill on the other side at ~40 % intensity (no shadows), rim from behind; a soft environment map (`RoomEnvironment` via `PMREMGenerator`) for reflections. Good for rooms, menus and character showcases.

### Post-processing (final version only)

One combined pass if possible: ambient occlusion, a little far blur (depth of field), a pastel colour grade (saturation, warmth), a soft vignette. Add a performance governor: when the frame time stays high, switch effects off first, then lower the resolution.

## 6. Animation in code

- One `play(name, fade = 0.2, force = false)` helper over an `AnimationMixer`; one-shot clips use `LoopOnce` + `clampWhenFinished`.
- Choose clips from movement with hysteresis and a 0.3 s minimum hold; turn with a damped yaw.
- Sync props to the clip's event frames (`action.time * 30` for 30 fps clips).
- Blinks, breathing, tail sway: in code or baked — they don't count against the 20 clips.

## 7. Camera

- FOV from aspect: portrait 58–62°, landscape 46–48°.
- Close third person: behind the shoulder, 1.2–3 m high, looking slightly ahead. When running from something, put the camera in front looking back at the chaser.
- At a choice: an over-the-shoulder shot that just fits every option, and it stays still until the choice is made.
- Short (~2 s) cinematic cut-ins with letterbox bars for big moments; cut or blend between shots.
- Never inside a character or a wall: clamp to the level bounds and ray-check towards the target.
